## 二、验收规则

**任务级（合并前，技术负责人把关）**

1. Issue 验收标准逐条打勾，每条对应自动化测试或实机验证记录。
2. 全量测试不新增失败（当前 3 个已知环境类失败单独登记为基线）。
3. 边界检查通过：核心模块不引用 pipeline / obsidian / quality / 模型网关；macOS 专属库不出现在采集 / HUD / 启动三层之外。
4. M1 起：安全门槛测试全部为 0；检索评测退化 ≤ 2 个百分点。
5. GitNexus 影响分析（项目规定）；索引停在 2026-05 且历史已改写，M0 第一步重建索引。
6. 仓库不出现任何真实采集数据（brain `no-real-data-in-repo`）。
7. 技术负责人审阅改动后合并，不以执行者自述为准。

**里程碑级**

- 出口门槛全部达成，附可复现演示脚本。
- 打标签作为回退点。
- 一页里程碑报告：完成内容、门槛结果、遗留问题、下一里程碑风险。

**执行方式**

- 每个 issue 一个分支 + PR，CI 通过且技术负责人审阅后合并进 `main`。
- 逻辑较重的任务由 Sonnet 执行，机械性任务由 Haiku 执行；技术负责人写任务说明、审阅、判断；需要产品负责人拍板的事项以选择题提出。
