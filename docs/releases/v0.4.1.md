## Penpal v0.4.1

修复版，解决 0.4.0 发布后在日常使用中发现的两个问题。两个问题都会让人以为 Penpal 坏了。

### AI 助手的查询不再在后台换新后失效

- 问题：Penpal 升级或改配置时会自动换上新代码，已打开的 Claude Code、Codex、Cursor 会话本应不受影响。但从第二次换新起，会话里每次查询都返回 `Invalid request parameters`，只能重开助手。
- 修复：每次换新都会把会话交接给新进程，不再只交接第一次（#162）。

### 菜单栏图标不再被误报为"被系统隐藏"

- 问题：在 macOS 26 上，菜单栏图标由系统的「控制中心」统一绘制。Penpal 原先用自己窗口的遮挡状态判断图标是否显示，这个信号在 macOS 26 上不代表用户实际看到的情况。结果是图标明明在显示，`penpal doctor`、`penpal hud status` 和 HUD 却报"图标被系统隐藏"，提示去系统设置里开关一次。多显示器、菜单栏图标较多时更容易出现。
- 修复：macOS 26 起只用系统给出的可见状态判断；macOS 15 及更早保持原判断（#163）。
- 已知限制不变：系统设置里「允许在菜单栏中显示」被关掉时，系统没有公开接口能读到，Penpal 无法确认，需要用户自己看一眼菜单栏。

### 升级

```bash
brew upgrade penpal
```

升级后后台服务、HUD 和 AI 助手连接都会自动换成新代码，不需要手动重启。

升级前已经出现 `Invalid request parameters` 的 AI 助手会话无法自行恢复，需要重开一次。
